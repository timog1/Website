Hydration & Server-Side Rendering

Understanding how Angular renders on the server and hydrates the client for optimal performance and SEO.

What is Server-Side Rendering (SSR)?

Server-Side Rendering (SSR) is a technique where the HTML for a web page is generated on the server and sent to the browser as a fully-formed document, rather than sending an empty HTML shell and letting JavaScript build the page in the browser.

In traditional Single Page Applications (SPAs), the browser downloads a minimal HTML file with a root element, then fetches JavaScript bundles, executes them, and constructs the DOM. This means search engine crawlers and users see an empty page until JavaScript finishes loading and executing.

With SSR, the server runs your Angular application, renders the initial view to HTML, and sends that HTML directly to the browser. Users see content immediately, and search engines can index the page content without executing JavaScript.

What is Hydration?

Hydration is the process where Angular takes the static HTML sent from the server and makes it interactive on the client side. After the browser receives the server-rendered HTML, Angular's JavaScript bundles load and "hydrate" the page by attaching event listeners, setting up data bindings, and initializing components.

Think of it like this: the server sends you a beautifully painted picture (static HTML). Hydration is the process of turning that picture into a living, breathing application where buttons respond to clicks, data updates in real-time, and navigation works seamlessly.

Before Angular 17, hydration required re-rendering the entire DOM — Angular would destroy the server-rendered DOM and rebuild it from scratch on the client. This caused a visible flash and wasted resources. Angular 17 introduced Incremental Hydration, which reuses the server-rendered DOM and only attaches the necessary event listeners and bindings.
