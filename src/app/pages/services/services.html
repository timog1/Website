What are Services?

Services are a big part of any Angular app. An Angular service is typically an object with a narrow, well-defined purpose. It should do something specific and do it well. Services are identified by the @Injectable() decorator.

Services are used to:

  • Share data across multiple components
  • Handle HTTP requests to backend APIs
  • Encapsulate business logic
  • Access browser APIs (localStorage, sessionStorage)
  • Manage application state

Dependency Injection (DI)

Dependency Injection (DI) is a design pattern used for implementing Inversion of Control (IoC). Angular has its own DI framework, and it's usually the preferred way to handle dependencies. It's also a form of third-party library integration.

The DI pattern means that a class requests dependencies from external sources rather than creating them itself. Angular's DI is hierarchical — providers are registered at different levels, and a component can access services from its own injector or from parent injectors.

Singleton Services

A singleton service has exactly one instance shared across the entire application. This is the most common pattern for services that manage shared state or provide utility functions.

⚠️ Common Mistake

Using providedIn: 'any' creates a new instance per lazy-loaded module, breaking the singleton pattern. Always use providedIn: 'root' for true singletons.
